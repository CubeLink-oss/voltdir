### 對比一般 Python 腳本

很多人以為幾行 Python 就能做到一樣快。這一節用同一套量測方法，把 Python 放進來：`python-scandir` 是一般人會寫的單執行緒 `os.scandir` 迴圈，`python-scandir-threads` 是同一支腳本用 4 個工作執行緒。兩者都和其他對照組做一樣的事（走一遍、邊走邊彙總、不跟隨符號連結與 junction），在 100 萬檔案的樹上算出的總量與標準答案相符。

| 資料夾 | 檔案數 | 資料夾數 | voltdir | 一般 Python 迴圈 | Python 多執行緒 | Python 要花 |
|---|---|---|---|---|---|---|
| B5，100 萬檔案的樹 | 1,000,000 | 5,059 | 0.45 秒、14.1 MB | 2.40 秒、15.8 MB | 3.04 秒、16.8 MB | **5.3 倍時間** |
| 開發工作區（`py-workspace`） | 296,839 | 57,680 | 3.10 秒、19.9 MB | 6.15 秒、16.6 MB | 未量測 | **2.0 倍時間** |
| 整顆資料磁碟（B2，`py-drive`） | 1,913,115 | 142,848 | 9.82 秒、27.9 MB | 19.69 秒、23.2 MB | 未量測 | **2.0 倍時間** |

怎麼讀這張表：

- **Python 比較慢，而且加執行緒不會變快。** 4 個執行緒是 3.04 秒，比單執行緒的 2.40 秒慢（全域直譯器鎖）。另外單次試跑 8、16、24 個執行緒分別是 6.4、6.4、8.3 秒，更慢；所以單執行緒迴圈就是 Python 的最佳情況。
- **差距跟資料夾的形狀有關。** 100 萬檔案的樹平均每個資料夾約 198 個檔案，差距最大（5.3 倍）；開發工作區平均每個資料夾約 5 個檔案、整顆磁碟約 13 個，差距縮到 2 倍左右。資料夾又多又小時，時間主要花在開啟資料夾，這個成本每個工具都一樣（見上方「為什麼一般權限的整碟掃描沒有贏」）。
- **記憶體差不多。** 100 萬檔案的樹上 voltdir 14.1 MB、Python 15.8 MB；在較大的樹上 Python 反而少用幾 MB（工作區 16.6 對 19.9 MB、整顆磁碟 23.2 對 27.9 MB，voltdir 約 0.83 倍），因為寫得仔細的 Python 腳本也是邊走邊彙總。
- 整顆資料磁碟那一格，Python 的 5 次裡有 1 次是 34.39 秒（其餘約 19.5 到 21.2 秒），中位數不受影響。兩個工具算出的檔案數一致（1,913,115）。

**基準腳本的一項修正：** 根目錄是磁碟機根（例如 `D:\`）時，舊版對照組腳本會把結尾的反斜線去掉，變成「`D:`」，Windows 把它解讀成 D: 的**目前資料夾**，而不是根目錄；如果工作資料夾剛好在同一顆磁碟，就會量到錯的資料夾（檔案數對不上時 `Measure-Tools.ps1` 會警告，這次就是因此發現）。四支對照組腳本都已修正。先前 `C:\` 的量測因為工作資料夾在別的磁碟，不受影響。

## 計數正確性（junction 與硬連結）

這一節比的是「數得對不對」，不是速度，所以只量一次，不換算倍數。樣本是一個約 30 萬個檔案的開發工作區（含大量 `node_modules`），裡面有 1,848 個 junction 與 5 個符號連結。

| 方法 | 檔案數 | 資料夾數 | 邏輯大小 | 實際佔用 |
|---|---|---|---|---|
| voltdir（預設） | 296,839 | 57,680 | 94.6 GB | 78.7 GB |
| voltdir `--hardlinks none` | 296,839 | 57,680 | 94.6 GB | 79.0 GB |
| voltdir `--follow-links junction` | 380,629 | 64,091 | 95.9 GB | 78.7 GB |
| 一般 Python `os.scandir` 迴圈（3.13） | 380,635 | 64,089 | 95.9 GB | 不量 |

怎麼讀這張表：

- 28% 的差距**完全來自 junction**。voltdir 預設不跟隨 junction；加上 `--follow-links junction` 後，檔案數與 Python 只差 6 個（量測期間有檔案變動）。
- 關掉硬連結去重（`--hardlinks none`）檔案數**一點也沒變**，只有實際佔用多了 0.3 GB。所以硬連結不是差距的原因。
- 跟隨 junction 之後，實際佔用仍是 78.7 GB：多出來的 8 萬多個檔案，是同一批檔案透過 junction 又被算了一次。

自己重現：

```powershell
voltdir overview <資料夾> -q
voltdir overview <資料夾> -q --follow-links junction
voltdir overview <資料夾> -q --hardlinks none
```

```python
import os, sys
files = dirs = 0
stack = [sys.argv[1]]
while stack:
    try:
        with os.scandir(stack.pop()) as it:
            for e in it:
                try:
                    if e.is_dir(follow_symlinks=False):
                        dirs += 1
                        stack.append(e.path)
                    else:
                        files += 1
                except OSError:
                    pass
    except OSError:
        pass
print(files, dirs)
```

在這次用的 Python 3.13 上，`DirEntry.is_symlink()` 對 junction 回傳 False（量到 5 個符號連結、1,848 個 junction），所以上面的迴圈不會把 junction 當成連結跳過，而是走進去。結果因資料夾而異；沒有 junction 的樹不會有這個差距。

## 連續追問：名稱索引（`.nidx`）

同一台機器、一般權限（不提權）、`C:\Users\<user>`（2,585,095 個檔案，含 AppData 與工具快取）。對照組是一支約 15 行的審慎 Python 腳本（`os.scandir` 迭代、不跟隨連結、不分大小寫的 `re.search`、統計讀不到的目錄）。問題是 `USE-CASES` 裡的 11 個檔名樣式。

| 項目 | 數值 |
|---|---|
| 冷：`scan --out`，不寫索引 | 58.4 秒 |
| 冷：`scan --out`，寫 `.idx` 與 `.nidx` | 60.3 秒（建索引多約 3%） |
| 快照／`.nidx`／`.idx` 大小 | 1,355 MB／283 MB（快照的 21%）／3 MB |
| 溫：`find --snapshot` 每題，11 題平均（各 3 次取中位數） | **1.04 秒**（0.70 到 2.05 秒） |
| 直接重掃的 Python 腳本，每題（3 個樣式取中位數，同一時段執行） | 53.1 秒 |
| 每題倍數 | **約 51 倍** |

連問 N 題的總時間（直接重掃 = N × 53.1 秒；voltdir = 冷掃描 60.3 秒 + N × 1.04 秒）：

| N | 直接重掃 | voltdir | 倍數 |
|---|---|---|---|
| 1 | 53 秒 | 61 秒 | 0.9 倍（**第一題沒有優勢**） |
| 3 | 159 秒 | 63 秒 | 2.5 倍 |
| 11 | 584 秒 | 72 秒 | **8.1 倍** |
| 30 | 1,593 秒 | 91 秒 | **17.4 倍** |

怎麼讀：

- **優勢只在追問。** 第一題要先掃描並建索引，和 Python 打平（甚至略慢）；從第三題起才領先。
- 每題 1 秒左右的下限來自：讀欄位（驗證區段雜湊）、對 258 萬個名稱做比對（現在分給所有核心同時做）。最慢的是帶多選的 regex（`(\.bak|\.old|~|\.tmp|\.crdownload)$` 約 2.05 秒、`(發票|invoice|receipt|收據)` 約 1.68 秒）；`--ext` 這類不比對名稱的條件約 0.03 秒。正規表示式引擎本身還沒有加速，是下一個瓶頸。
- 11 題的命中數：20、776、411、700、9,308、1,762、252、2、43、16,269、16,743。這是快照當下的結果；Python 在幾分鐘後執行，使用者目錄一直在變動（例如暫存檔 1,755 到 1,762），所以**不拿跨時間的命中數互相比較**。同一份快照下，索引與串流讀快照的輸出逐位元組相同，由 `tests/nidx.rs` 的條件矩陣保證（含 CJK、代理字元、方向控制字元、硬連結、多根、被裁剪的快照）。
- 並行化之前的第一版（單執行緒比對）每題平均 3.17 秒、倍數 17 倍，N = 11 為 6.5 倍；並行比對加上重複使用正規表示式的暫存空間之後才到上表。
- 一台機器、一棵樹、一個時段；Python 的時間會隨機器負載漂移（同一支腳本早先量到 33 到 38 秒，這個時段是 53 秒），倍數請當作這個時段的結果。

### 整理 PDF：聊天軟體自動下載的檔案

同一台機器、同一棵 `C:\Users\<user>`（一般權限）。先掃描並建索引，再依序問 7 個整理 PDF 的問題（都用 `--ext .pdf`，不比對名稱）：

| 項目 | 結果 |
|---|---|

| 有幾個 PDF（`--limit 0`） | 0.04 秒，728 個 |

## 量法規則

1. 每格至少 5 次，取中位數；少於 5 次不換算倍數。
2. 倍數只在同一個量測項目內計算，並寫明量的是什麼。
3. 對照組取最強的：耗時取最快、記憶體取最低。
4. 系統管理員與一般權限、暖快取與冷快取不混在同一格。
5. 量測期間有其他程序占用 CPU 時加註雜訊警告，警告不刪除。
6. 沒量到的情境寫「未量測」，比較慢的照實寫。
