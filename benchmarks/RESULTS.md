# 基準結果摘要

這份摘要列出 README 圖表背後的數字。每一格都是 **5 次量測的中位數**，對照組取**最強的一個**（通常是 `dotnet-enum-stream`）。用同一組腳本就能在你的機器上重跑，做法見 [`README.md`](README.md)。

**未達標的項目照列，不隱藏。** 倍數小於 1 代表 voltdir 比較慢或比較耗記憶體。

## 量測環境

| 項目 | 內容 |
|---|---|
| 作業系統 | Windows 11 x64，Microsoft Defender 即時防護開啟 |
| CPU | 12 核心、24 執行緒的筆電處理器 |
| 快取 | 暖快取：每個工具先暖機 1 次（不計入），再量 5 次 |
| 雜訊 | 量測期間有其他程序占用約 1 到 4 顆核心；腳本在每筆紀錄標註，數字應視為參考值 |
| 資料 | 100 萬檔案的樹由 `New-BenchTree.ps1` 以固定種子產生；整顆磁碟是實際使用中的 `C:\`（約 310 萬個檔案） |

## 情境代號

| 代號 | 情境 |
|---|---|
| B1 | 整顆磁碟，系統管理員：總量、前 20 大資料夾與檔案、前 10 個副檔名 |
| B2 | 同 B1，一般權限 |
| B3 | 掃一次，再追問 5 個不同的問題 |
| B5 | 100 萬檔案的樹，一次回答常見問題 |

## 工具層級（可用本倉庫的腳本重跑）

### 100 萬檔案的樹，一般權限

| 情境 | 量的是什麼 | voltdir | 最強對照組 | 倍數 |
|---|---|---|---|---|
| B5 | 耗時 | 0.65 秒 | 1.11 秒（`dotnet-enum-stream`） | 快 1.7 倍 |
| B5 | 峰值記憶體 | 14.3 到 14.7 MB | 163 MB（`dotnet-enum-stream`、`powershell-gci` 都約 163 MB） | 少約 11 倍 |
| B5 | 耗時，對常見的 `Get-ChildItem` 寫法 | 0.65 秒 | 55.6 秒（`powershell-gci`，另一次量測） | 快約 85 倍 |
| B3 | 掃一次加 5 個追問（`--save-index`），總耗時 | 1.51 秒 | 1.55 秒（一次走訪算完所有答案） | 1.03 倍（打平） |
| B3 | 同上，峰值記憶體 | 15.1 MB | 162.8 MB | 少約 10.8 倍 |

### 整顆 C:\（約 310 萬個檔案）

| 情境 | 量的是什麼 | voltdir | 最強對照組 | 倍數 |
|---|---|---|---|---|
| B1（系統管理員） | 耗時 | 6.56 秒（`mft` 引擎） | 37.45 秒 | 快約 5.7 倍 |
| B1（系統管理員） | 峰值記憶體 | 186 MB | 177 MB | 0.95 倍（打平） |
| B2（一般權限） | 耗時 | 54.4 秒（`walk` 引擎） | 42.3 秒 | **0.78 倍（較慢）** |
| B2（一般權限） | 峰值記憶體 | 144 MB | 175 MB | 少 1.2 倍 |
| B3（一般權限） | 掃一次加 5 個追問，總耗時 | 58.6 秒 | 43.0 秒 | **0.73 倍（較慢）** |

**為什麼一般權限的整碟掃描沒有贏：** 時間主要花在 NTFS 逐一開啟目錄，而且這個成本會隨執行緒數增加；試過以完整路徑、檔案識別碼、父目錄相對開啟三種方式，都一樣慢。系統管理員身分下的 `mft` 引擎直接讀主檔案表，不必逐一開啟目錄，所以快得多。

**追問的單次耗時：** 存好索引後，每個追問在 100 萬檔案的樹上約 0.02 到 0.04 秒，在整顆 `C:\` 上約 0.1 秒；不用索引、改讀整份快照時，分別約 3 秒與 22.5 秒。

## agent 層級（做法說明，工具不在本倉庫）

同一個模型、同樣的權限、逐字相同的題目，只差一句「可以使用 voltdir」或「只能用 PowerShell／.NET」。每組各 5 次，答錯的不計入。耗時是每一輪回應時間的加總。

| 情境 | voltdir 組 | 基準組 | 結果 |
|---|---|---|---|
| 連續追問 6 題（100 萬檔案的樹） | 46.2 秒、11 次呼叫 | 220.1 秒、13 次呼叫 | 快約 4.8 倍，全部答對 |
| 比較兩個不同路徑的資料夾 | 10.4 秒、3 次呼叫 | 21.3 秒、3 次呼叫 | 快約 2 倍 |
| 一次回答 100 萬檔案的常見問題 | 10.7 秒、3 次呼叫 | 17.2 秒、3 次呼叫 | 快約 1.6 倍 |
| token 用量 | 比基準組多 4% 到 10% | — | 每次呼叫約 7.3 萬 token 是 agent 的固定開銷，工具改善不了 |

## 量法規則

1. 每格至少 5 次，取中位數；少於 5 次不換算倍數。
2. 倍數只在同一個量測項目內計算，並寫明量的是什麼。
3. 對照組取最強的：耗時取最快、記憶體取最低。
4. 系統管理員與一般權限、暖快取與冷快取不混在同一格。
5. 量測期間有其他程序占用 CPU 時加註雜訊警告，警告不刪除。
6. 沒量到的情境寫「未量測」，比較慢的照實寫。
